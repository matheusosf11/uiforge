# Phase 8 — UI Design Contract

> Visual and interaction contract for the Editable Code View. Generated by gsd-ui-researcher, verified by gsd-ui-checker. Decisions D-01..D-17 from `08-CONTEXT.md` are locked and reflected here. Everything else is a Claude's-discretion choice, marked "(default)". Tokens, type scale, colors, copy conventions and the transient item style are inherited from the approved `06-UI-SPEC.md` and `07-UI-SPEC.md`.

> **Focal point:** the preview stays the primary visual anchor. The code panel keeps today's look: same panel, same nightOwl / nightOwlLight colors, same padding and font. It only adds a caret, a focus ring, an "Editado" badge, one extra header button and a one-line hint. Editing must feel like typing into the panel that is already there, not like a new IDE widget.

## Typography

No new sizes or weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (status line, dialog description) | 14px (`text-sm`) | 400 | 1.5 |
| Label (header buttons, "Editado" badge, hint, transient item text) | 12px (`text-xs`) | 400; 500 (`font-medium`) for the "Editado" badge | 1.5 (badge uses `leading-5` inside `h-5`) |
| Heading (panel title "Código"; AlertDialog title) | 14px (`text-sm`) for the panel title; 16px (`text-base`) for the dialog title | 500 | 1.2 |
| Code (editor, unchanged from today's `pre`) | 12px (`text-xs`), `font-mono` | 400 | 1.625 (`leading-relaxed`) |

Declared set: sizes 12 / 14 / 16; weights 400 and 500.

**Editor font rule (must hold for both layers):** the textarea and the highlighted layer must have the identical `font-family`, `font-size` (12px), `line-height` (1.625), `letter-spacing` (normal), `tab-size` (2) and padding (12px). Any mismatch makes the caret drift from the visible text. Apply them on the editor root so both children inherit (default: `className="font-mono text-xs leading-relaxed"` on the editor plus `style={{ ...prismTheme.plain, tabSize: 2 }}`, and `textareaClassName="outline-none"`).

Accent reserved for (inherited, unchanged):
1. The primary submit button "Gerar"/"Refinar".
2. The selected suggestion or example chip.

Editor colors:
- Caret: `caret-color` = prism `plain.color` (#d6deeb dark, #403f53 light), so it is visible on both backgrounds.

- Read-only: no dimming, no color change. Streaming code must stay fully readable.

## Component Contracts

### 1. Code panel shell (`code-view.tsx`) (D-13, D-16)

- Section: unchanged classes `flex h-full min-h-64 min-w-0 flex-col overflow-hidden rounded-xl border border-border bg-card p-4`. Replace `aria-label="Generated code"` with `aria-labelledby` pointing at the panel title (default id `code-panel-title`). Update tests that query "Generated code".
- Header row: `mb-2 flex flex-wrap items-center justify-between gap-2` (adds `flex-wrap` so three buttons fit on narrow widths).
  - Left group `flex items-center gap-2`: `h2#code-panel-title` with text **`Código`** (was "Código gerado", D-16), then the "Editado" badge when a draft exists.
  - Right group `flex flex-wrap gap-2`, in this order: **Descartar edições** (only when a draft exists), **Copiar**, **Baixar**.
- Layout target (desktop): `Código  [Editado]          [x Descartar edições] [Copiar] [Baixar]`.

**"Editado" badge** (D-13): `<span class="inline-flex h-5 items-center rounded-md bg-muted px-2 text-xs leading-5 font-medium text-foreground">Editado</span>`. Plain text, not a live region (the turn list item and the status line carry the semantics). It appears on the first keystroke that makes the text differ from the base, and disappears when the text equals the base again (D-06), on discard, and on commit.

**Descartar edições button** (D-13):
- `Button type="button" variant="outline" size="sm" className="text-xs max-md:min-h-11"`, icon `X` (`aria-hidden`), label `Descartar edições`.
- Rendered only while a draft exists and the editor is editable (not while streaming; there is no draft then anyway).
- Click: the editor value reverts to the base version code instantly, no confirmation. The preview follows immediately (no debounce, it is a revert). The badge and the transient item disappear.
- Focus after click: the button unmounts, so move focus to the editor textarea (default). Caret at the start.
- The editor's own undo stack still works afterward (Ctrl/⌘+Z inside the editor can bring the edit back, as native textarea behavior allows; do not promise more).

**Copiar / Baixar** (D-17, EDIT-07): unchanged look, labels and states (`Copiar` / `Copiado` / `Não foi possível copiar`, `Baixar`). They export exactly the editor's current text, draft included, and `componentFilename` uses that text. Disabled while busy or when the text is empty after trim (unchanged rule). The copy fallback selects the editor content (select the textarea's text) instead of the `pre`.

### 2. Editor surface (D-01..D-05, EDIT-04)

Replaces today's `<pre>` in the same place, with the same box:

```
<div ref={scrollRef}
     class="max-h-[70vh] flex-1 overflow-auto rounded-lg
            focus-within:ring-3 focus-within:ring-ring/50"
     style={{ backgroundColor: prismTheme.plain.backgroundColor }}>
  <Editor
    value={code}
    onValueChange={onChange}
    highlight={(c) => /* prism-react-renderer Highlight → tokens as today */}
    padding={12}
    tabSize={2} insertSpaces
    readOnly={readOnly}
    textareaId="code-editor"
    textareaClassName="outline-none"
    className="min-h-full font-mono text-xs leading-relaxed"
    style={{ ...prismTheme.plain, caretColor: prismTheme.plain.color }}
    /* textarea attrs */ aria-label="Editor de código"
                         aria-describedby="code-editor-hint"
                         spellCheck={false} autoCapitalize="off" autoCorrect="off" autoComplete="off"
  />
</div>
<p id="code-editor-hint" class="mt-2 text-xs text-muted-foreground">Esc e depois Tab para sair</p>
```

- **Scroll container:** the wrapper `div` scrolls, not the textarea (the textarea grows with its content). `scrollResetKey` now resets the wrapper's `scrollTop` to 0 in a layout effect (undo, restore, D-12 of Phase 7). Also reset the textarea selection to the start on those events (default).
- **Wrapping (deliberate change):** both layers use `white-space: pre-wrap` with `overflow-wrap: anywhere` (the library default), so long lines soft-wrap instead of scrolling horizontally. An overlay editor needs identical wrapping on both layers, and this also removes horizontal scrolling on mobile. No line numbers (D-03).
- **Focus ring:** shown on the wrapper via `focus-within:ring-3 focus-within:ring-ring/50`; the textarea itself has `outline-none`. The section's `p-4` leaves room so the 3px ring is not clipped by `overflow-hidden`.
- **No placeholder text inside the editor** (default). If the user deletes all code, the editor stays (empty, focused); Copiar/Baixar disable; the preview shows its error state (D-12).

**Editor states:**

| State | Condition | Editor | Hint | Header |
|-------|-----------|--------|------|--------|
| Empty (no version yet, not streaming) | no committed version and no code | Not rendered. Keep today's placeholder `<p>` (dashed border, `O código gerado aparecerá aqui.`) | not rendered | `Código`, Copiar/Baixar disabled |
| Streaming (first generation or refine) | `busy` | Rendered with the live streamed code, `readOnly` (D-05). Caret may show but typing does nothing; text is selectable. Tab/Shift+Tab/Escape are **not** intercepted while read-only, so Tab moves focus out normally. | rendered (stays, avoids layout shift) | Copiar/Baixar disabled (unchanged), no badge, no Descartar |
| Editable, clean | ≥1 version, not busy, text equals base | editable | rendered | `Código`, Copiar, Baixar |
| Editable, draft | ≥1 version, not busy, text differs from base | editable | rendered | `Código [Editado]`, Descartar edições, Copiar, Baixar |

- Read-only uses the textarea `readOnly` attribute (not `disabled`), so focus is not lost when a refine starts while the user is in the editor. No opacity change, no "bloqueado" label: the status line "Refinando…"/"Gerando…" and the transient "gerando…" item already signal busy.
- Mobile (D-04): the same editor in the Código tab, same states. No extra toolbar, no mobile-specific features. The Código tab is not auto-selected by any draft event.

### 3. Keyboard contract (D-02, EDIT-08)

| Input (editor focused, editable) | Behavior |
|----------------------------------|----------|
| Typing | Edits the text; creates or updates the draft |
| Tab | Inserts 2 spaces at the caret, or indents every selected line by 2 spaces |
| Shift+Tab | Removes up to 2 leading spaces from the current or selected lines |
| Escape | Enters "exit mode". Does not blur, does not change the text, does not move the caret |
| Tab / Shift+Tab right after Escape | Not intercepted: focus moves to the next / previous focusable element (no keyboard trap) |
| Any other key after Escape | Leaves exit mode (default) |
| Focus leaving and re-entering the editor | Exit mode is reset to off (default) |
| Ctrl/⌘+Z, Ctrl/⌘+Shift+Z / Ctrl+Y | Native textarea undo/redo inside the editor. The global session undo shortcut ignores the editor because it is a textarea (inherited rule) |
| Ctrl/⌘+Enter | No special behavior in the editor (default); it only submits from the prompt textarea |

- When the editor is read-only, Tab, Shift+Tab and Escape are never intercepted.
- Escape inside an open AlertDialog closes the dialog (unchanged); the editor is not reachable while a dialog is open.
- Tab order of the result column: tabs (mobile) → preview → Código header (Descartar edições when shown, Copiar, Baixar) → editor. The hint is not focusable.
- The hint `Esc e depois Tab para sair` is always visible under the editor (desktop and mobile) and linked with `aria-describedby="code-editor-hint"`. It is static text; it does not change in exit mode.

### 4. Draft → preview (D-11, D-12, EDIT-05)

- The preview receives the draft text **500 ms after the last keystroke** (trailing debounce). Undo, restore, discard, commit and reset update the preview immediately (no debounce) and cancel any pending debounce.
- No "Atualizando…" badge for draft updates (D-11). The iframe is not dimmed and shows no placeholder while waiting.
- Broken draft code (syntax error, runtime error, or no `export default`) shows the existing SandboxPreview error state, unchanged in look and copy. It recovers on its own when a later debounced text renders cleanly.
- The preview's `Tentar de novo` (regenerate) is **not rendered** while a draft exists (D-12). Also hidden when the current version is `source: "manual"` (default: there is no AI instruction to replay, and the error comes from the user's code). Otherwise the Phase 7 `canRegenerate` rule applies unchanged.

### 5. Turn list: draft transient item (D-14)

- New `TransientTurnItem` kind `"rascunho"`, in the exact Phase 7 transient row (`ROW` classes, non-interactive `<div>` inside an `<li>`, always last in the `<ol>`).

| Slot | Content | Classes |
|------|---------|---------|
| Label | empty (`min-w-7` spacer) | `min-w-7 shrink-0` |
| Text | `Edição manual (rascunho)` | `min-w-0 flex-1 truncate text-muted-foreground`, `title="Edição manual (rascunho)"` |
| Status word | none | - |
| Icon | `Pencil` | `size-4 shrink-0 text-muted-foreground`, `aria-hidden="true"` |

- Accessible text: the visible text is read as is (`Edição manual (rascunho)`); no `sr-only` prefix needed.
- At most one transient item (inherited). Precedence: `gerando` > `rascunho` > `erro`. Typing a draft after a failed refine replaces the `erro` item with the `rascunho` item (default; the error banner stays until the usual clear events).
- The item is always at the end of the list, also when the draft is on an older, restored version (D-08). The later versions stay dimmed and the base notice stays visible.
- The list auto-scrolls to the draft item when it first appears (inherited Phase 7 rule: scroll the list container only).
- On commit it is replaced by the committed item `v{N}` with text `Edição manual` and `Check` (Phase 7 contract, already implemented), which becomes current.
- It disappears on discard, when the text returns to the base, and on reset.

### 6. Commit-before-action sequencing, visible results (D-07, D-08, D-10, D-15)

A draft is committed as a `source: "manual"` version right after its base (dropping later versions, D-08) before these actions. "M" is the new version's stable display number; "N" is the base's.

| Action while a draft exists | Visible result | Status line (single `aria-live="polite"`) |
|-----------------------------|----------------|-------------------------------------------|
| Refinar (button or Ctrl/⌘+Enter) | Draft item becomes `vM · Edição manual ✓` (current); then the `gerando…` item appears; the refine uses vM's code as base | `Edição salva como vM`, then immediately `Refinando…` (D-15) |
| Desfazer (button or Ctrl/⌘+Z outside fields) | vM is committed, then the cursor goes to vN (the original). vM stays in the list, dimmed as a later version, restorable | `Edição salva como vM · Voltou para vN` (default) |
| Click on an earlier version vK | Commit vM, then restore vK. vM stays restorable (dimmed) | `Edição salva como vM · Voltou para vK` (default) |
| Click on the base item vN (the current item) | Commit vM, then restore vN (same as Desfazer). Not a no-op while a draft exists | `Edição salva como vM · Voltou para vN` (default) |
| Click on a later, dimmed version vX (draft on older vN) | D-09 dialog (§7). No commit | unchanged until confirm |
| Novo componente | The confirmation dialog opens because the draft counts as a manual edit; confirm resets (no commit needed, everything is discarded) | `Novo componente iniciado` (unchanged) |

Rules:
- **Desfazer is enabled while a draft exists, even on v1** (commit to v2, then undo to v1). It stays disabled while busy.
- Refinar with a broken draft is allowed (D-10): no inline validation, no warning; the manual version is saved as-is.
- **Size limit:** if the draft exceeds `MAX_CODE_LENGTH`, Refinar still commits the manual version first, then the client pre-check fails and the existing `CODE_TOO_LARGE_MESSAGE` banner appears with its `Novo componente` action; no request is sent (default). No character counter is added to the editor.
- E2E/tests: the existing strings `Pronto — vN` and `Voltou para vN` are kept; combined messages contain `Voltou para vN` as a substring, so assertions must use substring matching.

### 7. "Discard draft" AlertDialog (D-09)

Clone of `NewComponentDialog` (same component, same focus handling), new file `discard-draft-dialog.tsx` (default).

| Part | Content |
|------|---------|
| Title (`AlertDialogTitle`, 16px/500) | `Descartar edições?` (default) |
| Description (`AlertDialogDescription`, 14px/400) | `Você tem edições na vN. Ir para a vX descarta essas edições.` |
| Cancel (`AlertDialogCancel`, outline, initial focus) | `Cancelar` |
| Confirm (`AlertDialogAction`, destructive variant) | `Descartar edições e ir` |

- Trigger: only a click (or Enter/Space) on a later, dimmed version while a draft exists on an older base. This is the only confirmation in the phase.
- Confirm: drop the draft (no commit), restore vX, status `Foi para vX` (inherited). Cancel or Escape: nothing changes, the draft stays.
- Focus: initial focus on `Cancelar`. On close (either way) focus returns to the clicked turn item (items are keyed by version id, so the element survives the restore, Phase 7 D-19).

### 8. Motion

No new motion. No debounce indicator, no badge fade, no list animation. The `Pencil` icon is static. AlertDialog uses the shadcn default enter/exit (already honors reduced motion through the existing component).
