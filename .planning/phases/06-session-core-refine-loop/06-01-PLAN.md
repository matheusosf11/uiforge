  <behavior>
    - START with no pending: sets pending {id, instruction, baseId = versions[cursor]?.id ?? null, text ""}, clears error and notice; START while pending !== null is a no-op
    - CHUNK with matching id sets pending.text to the provided FULL text; mismatched id or no pending is a no-op
    - COMMIT with matching id: code = parseCode(raw); empty/whitespace code or !hasDefaultExport(code) -> error {kind "invalid", instruction, baseId}, pending null, versions/cursor untouched
    - COMMIT valid: kept = versions up to and including the index of pending.baseId (empty when baseId null), append {id: nextVersionId, code, instruction, source "ai"}, drop oldest while length > MAX_VERSIONS, cursor = last, pending null, error null, notice "committed", nextVersionId + 1
    - FAIL matching id: pending null, error {kind, instruction, baseId} taken from pending, notice null, versions/cursor untouched; ABORT matching id: pending null, error null, notice null; stale ids no-op
    - REJECT: sets error {kind "too_large", instruction, baseId = versions[cursor]?.id ?? null} without creating pending; ignored when pending
    - UNDO only when canUndo: cursor - 1, keeps later versions, error null, notice "undo"
    - RESET (not blocked by reducer): versions [], cursor -1, pending null, error null, notice "reset", nextVersionId preserved
    - Scenarios: v1,v2,v3 -> UNDO,UNDO -> refine COMMIT => versions [v1, new] cursor 1; 21st commit drops oldest and cursor stays last with ids monotonic; stale CHUNK/COMMIT after ABORT leaves versions empty; retry after FAIL (START again) reuses same baseId
  </behavior>
