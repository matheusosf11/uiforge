# Phase 6 — UI Design Contract

> Visual and interaction contract for Session Core & Refine Loop. Generated by gsd-ui-researcher, verified by gsd-ui-checker. Decisions D-01..D-16 from 06-CONTEXT.md are locked and reflected here; everything else is documented Claude's-discretion choice (marked "default").

> **Focal point:** the preview panel is the primary visual anchor; the prompt textarea is the primary action area; the session bar and the "Atualizando…" badge are secondary cues.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (components.json present, style `base-nova`) |
| Preset | base-nova, baseColor neutral, CSS variables, Tailwind v4 tokens in `src/app/globals.css` |
| Component library | base-ui (shadcn base-nova); existing: `button`, `textarea`, `loom-draft` |
| Icon library | lucide-react (`RotateCcw`, `Undo2`, `FilePlus2`, `Loader2`/`Sparkles` only if needed) |

Reuse everything existing: panel shell `rounded-xl border border-border bg-card p-4`, panel title `text-sm font-medium text-muted-foreground`, error banner `rounded-lg border border-destructive/40 bg-destructive/10 px-3 py-2 text-sm text-destructive`, chip = `buttonVariants({variant:"outline", size:"sm"}) + text-xs`.

## Component Contracts

### 1. Prompt panel (PromptForm) — mode switch (D-01..D-03)

| State | Panel title (`h2`) | Textarea `aria-label` | Placeholder | Submit button |
|-------|-------------------|----------------------|-------------|---------------|
| Generate (no committed version) | `Prompt` (unchanged) | `Prompt` | `Descreva um componente de UI… (⌘/Ctrl+Enter para gerar)` | `Gerar` |
| Refine (>=1 committed version) | `Refinar componente` | `Descreva a mudança` | `Descreva a mudança… (⌘/Ctrl+Enter para refinar)` | `Refinar` |

- Same textarea, layout, char counter (`N/MAX_PROMPT_LENGTH caracteres`), `Parar` secondary button while busy. Textarea `disabled` while busy (existing).
- Text is cleared only on commit (D-02). On failure/stop the text stays.
- Button size/label change is instant; no animation. Submit keeps `type="submit"`; e2e selector `getByRole('button',{name:'Gerar'})` still valid for first generation.

### 2. Session bar (D-10)

- Rendered only when `versions.length >= 1`, as first child inside the prompt panel, above the panel title row: a single row `flex items-center justify-between gap-2 mb-2` (wraps on narrow widths via `flex-wrap`).
- Left: `<span class="text-xs text-muted-foreground tabular-nums">v3 de 5</span>` (format `v{cursor} de {total}`; with the 20 cap, total max is 20).
- Right group (`flex items-center gap-1`):
  - `Desfazer` — `Button variant="ghost" size="sm"` with `Undo2` icon (`aria-hidden`), `aria-keyshortcuts="Control+Z Meta+Z"`. `disabled` when busy or cursor is v1. Disabled style is the default shadcn (`opacity-50`, `pointer-events-none`); `title` set to `Desfazer (Ctrl/⌘+Z)` when enabled.
  - `Novo componente` — `Button variant="ghost" size="sm"` with `FilePlus2` icon (`aria-hidden`). `disabled` while busy.
- Wrap in `<div role="toolbar" aria-label="Sessão">` (arrow-key roving not required; plain Tab order: Desfazer then Novo componente then textarea).
- Visual separation from the title: `border-b border-border pb-2` is NOT used; keep a light layout (just `mb-2`) so Phase 7's turn list can be placed beneath.
- Mobile (`max-md`): buttons `min-h-11`, label text always shown (no icon-only), row wraps.

### 3. "Novo componente" AlertDialog (D-12, D-13)

- Trigger path: click `Novo componente`. If `versions.length === 1` (and no manual edits) reset immediately with no dialog. If more than 1 version, open AlertDialog.
- Content (pt-BR):
  - Title: `Começar um novo componente?`
  - Description: `Isso descarta todas as versões desta sessão. O texto do campo de prompt será mantido.`
  - Cancel: `Cancelar` (outline, default focus target is Cancel per base-ui behavior; Esc closes = cancel)
  - Confirm: `Descartar e começar` (destructive variant)
- A11y: focus trap, return focus to the `Novo componente` button on cancel; on confirm, move focus to the textarea (it is the next logical action). `role="alertdialog"` provided by the component.
- Overlay: shadcn default (`bg-black/10` + backdrop blur per base-nova); card surface `bg-popover`.
- After reset: versions/code/preview/suggestions/errors cleared, prompt field text kept, gallery returns, status line shows empty (and aria-live announces `Novo componente iniciado`).

### 4. Suggestion chips (ITER-09; D-03..D-09)

- Location: same area/position as the v1.0 example gallery (below the char counter, `mt-3 flex flex-wrap gap-2`), with an accessible group wrapper `role="group" aria-label="Sugestões de refinamento"`. In Generate mode the gallery keeps `aria-label="Exemplos"` group (add if absent).
- Chip: identical visual to gallery chip (`outline` sm, `text-xs`); text = short label (<= ~30 chars, `truncate` with `max-w-full`); `title` = full instruction; `aria-label` = `{label}: {instruction}`; click prefills textarea with the full instruction (no send), selected state `aria-pressed` + `bg-primary text-primary-foreground` while the field equals that instruction (same logic as gallery). Disabled while busy. After prefill, focus moves to the textarea (cursor at end) so Ctrl/⌘+Enter is immediately usable.
- Loading: 4 skeleton chips, `h-8 rounded-lg bg-muted animate-pulse` with widths `w-24 / w-32 / w-28 / w-20` (all multiples of 4); wrapper `aria-busy="true"`; add `motion-reduce:animate-none`. No text announced.
- Fallback (failure/timeout/429, silent, D-08): `Modo escuro`, `Mais espaçamento`, `Adicionar ícone`, `Animação no hover`, with full instructions:
  - `Modo escuro` → `Adicione suporte a modo escuro com cores adequadas.`
  - `Mais espaçamento` → `Aumente o espaçamento interno e entre os elementos.`
  - `Adicionar ícone` → `Adicione um ícone adequado ao componente.`
  - `Animação no hover` → `Adicione uma animação sutil ao passar o mouse.`
- Transition skeleton -> chips: instant swap, no fade (avoid layout shift: the container reserves one row height `min-h-8`).
- While a refinement is streaming, show the previous chips (disabled) rather than skeleton; skeleton appears only when a new suggest request is in flight for the current version and no chips exist for it. After undo: show chips for that version if cached, otherwise fetch (skeleton), never show another version's chips (D-09).
- No visible error for suggestions ever.

### 5. Status line and aria-live (D-15, D-16)

Single polite live region at top of the right column (existing `<p aria-live="polite" aria-atomic="true" class="min-h-5 text-sm text-muted-foreground">`), always mounted (visible in both mobile tabs, since it sits above the tab list).

| Situation | Text |
|-----------|------|
| Idle / empty | (empty) |
| Generating first version | `Gerando…` (unchanged) |
| Refining | `Refinando…` |
| Commit success | `Pronto — v4` (N = new version number); persists until next action |
| Undo | `Voltou para v3` (default) |
| Reset | `Novo componente iniciado` (default; clears on next action) |
| Stopped by user | (empty) |
| Error | status empty; the error banner (role="alert") carries the message |

Rules: no flashy animation or color change on success; text stays `text-muted-foreground`. Suggestion chips arriving does NOT announce. Do not make the session counter live (avoids duplicate announcements).

### 6. Preview "Atualizando…" badge (D-14)

- Shown only while refining AND a committed previous version is rendered. Positioned top-right in the preview panel header row (the `h2 Preview` row becomes `flex items-center justify-between`), as a plain `<span>` (NOT a live region; the status line does the announcing).
- Style: `inline-flex items-center gap-1 rounded-md bg-muted px-2 py-1 text-xs text-muted-foreground` with a small `Loader2` (`size-3 animate-spin motion-reduce:animate-none`, `aria-hidden`) and text `Atualizando…`.
- The iframe is NOT remounted or dimmed; it keeps showing the last committed version (no flash). Preview swaps once, on a valid commit. The `Gerando preview…` placeholder is used only for the very first generation.
- Mobile: the badge sits in the Preview tab; status line "Refinando…" covers the Código tab.

### 7. Code panel during refine (D-14)

- Streams new code live (v1.0 behavior) via `CodeView busy`. On failure/stop reverts to last committed version's code. After undo, shows the code of the cursor version. No new chrome.

### 8. Error states

Banner reuses the existing destructive banner with `role="alert"`, placed above tabs.

| Case | Message | Actions |
|------|---------|---------|
| Refine failure/network/stream error/invalid result | `REFINE_ERROR_MESSAGE` (ends with "Sua versão anterior foi mantida.") | `Tentar de novo` (outline sm, `RotateCcw`) — re-sends the same instruction against the same base version |
| First-generation failure | existing `friendlyGenerateError(err, "generate")` copy | `Tentar de novo` (unchanged) |
| 413 `code_too_large` (server or client pre-check against `MAX_CODE_LENGTH`) | `CODE_TOO_LARGE_MESSAGE` | NO retry (it would fail again). Primary action `Novo componente` (outline sm, `FilePlus2`) which triggers the same reset flow (dialog if >1 version); the session bar `Novo componente` remains available |
| Rate limit 429 on refine | friendly copy from `friendlyGenerateError` | `Tentar de novo` |
| Preview runtime error on a refined version | existing SandboxPreview alert; its `Gerar de novo` button becomes `Tentar de novo` in refine mode and re-sends the last instruction | Undo remains available |

- Banner clears when a new send starts, on undo, and on reset. On a failed refinement the form text is preserved (D-02), preview and code panel stay at the last committed version, version counter unchanged.
- Focus: banner does not steal focus (role="alert" announces).

### 9. Keyboard and shortcuts (D-11)

| Shortcut | Behavior |
|----------|----------|
| Ctrl/⌘+Enter | Submit in textarea (existing); label of action follows mode |
| Ctrl/⌘+Z | Global `keydown` listener on `document`; calls undo ONLY if `event.target` is not `textarea`, `input`, `select`, or `[contenteditable]`, no dialog is open, not busy, and cursor > v1; `preventDefault()` only when it acts. Meta key on macOS, Ctrl elsewhere (accept either). Shift+Z (redo) is ignored. |
| Tab order | Session bar (Desfazer, Novo componente) -> textarea -> chips -> Gerar/Refinar -> Parar |
| Esc | Closes AlertDialog (cancel) |

Focus ring: existing `focus-visible:ring-3 focus-visible:ring-ring/50` on every new interactive element (shadcn Button already provides).

### 10. Mobile behavior (D-15)

- Layout order unchanged (`order-1` result column on top, form below on `max-md`). Session bar lives in the form panel (below on mobile). Because Desfazer is then below the preview, the status line stays above the tabs so "Refinando…"/"Pronto — vN" is visible in either tab.
- Current tab is preserved on send, success, failure, undo, and reset (no auto-switch).
- All new buttons/chips >= 44px tall on `max-md`; chips wrap; no horizontal scroll (labels truncate).
- Keyboard shortcuts are desktop only; buttons are the mobile path.

### 11. Motion

Only: `animate-pulse` skeleton chips and `animate-spin` badge loader, both with `motion-reduce:animate-none`. AlertDialog uses the shadcn default enter/exit. No transitions on preview swap.
