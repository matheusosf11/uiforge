# Phase 6: Session Core & Refine Loop - Context

**Gathered:** 2026-10-17
**Status:** Ready for planning

<domain>
## Phase Boundary

Client-side session + refine loop on top of the Phase 5 API. A pure, unit-tested session reducer (versions, cursor, pending; commit/undo/reset/truncate/20-cap/abort/error/stale-chunk guard) drives a reworked `GeneratorShell`: after the first committed version the form refines by default, the preview keeps the last good version while a refinement streams and swaps once on a clean valid result, failures/stops keep the previous version with a retry that reuses the same base, the user can undo (button + shortcut) and start over ("Novo componente" with confirmation). Refine suggestion chips are generated by the model via a new lightweight endpoint, with a fixed fallback list.

Requirements: ITER-01, ITER-02, ITER-05, ITER-06, ITER-07, ITER-08, ITER-09, UX-05, QUAL-06.

Out of this phase: visible turn list / click-to-restore / dimmed future versions (Phase 7), editable code + manual-edit versions (Phase 8), full e2e journey + GIF + READMEs (Phase 9). The reducer should still model versions so Phase 7/8 only add UI (e.g. a `source`/`kind` field on versions is fine to include now).
</domain>

<decisions>
## Implementation Decisions

### Carried forward (locked earlier — do not re-ask)
- Refine-by-default after the first committed version; model receives current code + instruction only (Phase 5 `currentCode` contract).
- Refining from an older version truncates the versions after it (no redo); max 20 versions in memory, oldest dropped; no persistence.
- A version is committed only if the stream finishes cleanly AND the parsed code is non-empty AND has `export default` (reuse `src/lib/has-default-export.ts`). Server already fails the body on mid-stream error and on non-"stop" finishReason.
- Oversized code: server returns 413 `code_too_large` → show `CODE_TOO_LARGE_MESSAGE` and offer "Novo componente"; client should also pre-check `MAX_CODE_LENGTH` before sending.
- Refine failure phrase: `REFINE_ERROR_MESSAGE` ("…Sua versão anterior foi mantida."); `friendlyGenerateError(err, mode)`.

### Form: Gerar → Refinar
- **D-01:** Same textarea/layout. After the first committed version: button label "Refinar", placeholder "Descreva a mudança… (⌘/Ctrl+Enter para refinar)", panel label "Refinar componente". Before it: v1.0 texts unchanged.
- **D-02:** The prompt field clears only when a refinement (or generation) is committed as a version; on failure/stop the text stays so the user can retry/edit.
- **D-03:** In refine mode the example gallery is replaced by refine suggestion chips in the same area; the gallery returns after "Novo componente".

### Refine suggestion chips (ITER-09)
- **D-04:** Suggestions are generated by the model automatically after each committed version (no click needed).
- **D-05:** New lightweight endpoint (e.g. `POST /api/suggest` with `{ code }`), its OWN rate-limit bucket (separate from generate/refine), lightest model (flash-lite first), short structured output (JSON via zod schema). Same safety posture as Phase 5: code is delimited as data, size-capped with `MAX_CODE_LENGTH`, env-gated e2e mock returns deterministic suggestions, never logs code.
- **D-06:** 4 chips, pt-BR. Each suggestion has a short label (≤ ~30 chars, shown on the chip) and a full instruction (put into the field on click).
- **D-07:** Clicking a chip PREFILLS the prompt field (does not send) — same as the v1.0 gallery.
- **D-08:** While loading: skeleton chips (3–4 pulsing placeholders). On failure/timeout/429: silently fall back to a fixed generic pt-BR list of 4 (e.g. "Modo escuro", "Mais espaçamento", "Adicionar ícone", "Animação no hover") — no error message.
- **D-09:** Stale-response guard: suggestions for an older version must never replace those of the current version (request id / version id check); undo/reset clears or reloads appropriately.

### Undo & Novo componente
- **D-10:** Session bar at the top of the prompt panel, shown only after the first version: "vN de M" · "Desfazer" · "Novo componente". (Phase 7's turn list will sit near it.)
- **D-11:** Undo shortcut: Ctrl/⌘+Z when focus is NOT in a text field (textarea/input/contenteditable keep native text undo). Submit stays Ctrl/⌘+Enter (already exists in prompt-form). Undo disabled while streaming and when at v1.
- **D-12:** "Novo componente" confirmation via an accessible shadcn AlertDialog (focus trap, Esc cancels) — only when there are multiple versions (or manual edits, once Phase 8 exists); with a single version it resets immediately.
- **D-13:** Reset clears versions, code, preview, suggestions and errors, but KEEPS whatever text is in the prompt field.

### Feedback during refine
- **D-14:** While a refinement streams, the code panel shows the new code streaming live (v1.0 effect); the preview keeps rendering the previous committed version with an "Atualizando…" badge. On failure/stop the code panel reverts to the last committed version.
- **D-15:** Mobile tabs: keep the current tab; "Refinando…" status visible in both tabs.
- **D-16:** On success: discreet status "Pronto — vN" plus an aria-live announcement; no flashy animation.

### Claude's Discretion
- Reducer/hook file layout (research suggests `src/lib/session.ts` + `use-generator-session.ts`), version `id` scheme, exact action names.
- Exact chip texts of the fallback list and the suggest prompt wording; suggest rate-limit numbers; suggest timeout (a few seconds).
- Whether `useCompletion` is kept (verify per-call `body` in installed `@ai-sdk/react`) or replaced by a small custom fetch/stream hook.
- How the "Atualizando…" badge and session bar look (follow existing shadcn/Tailwind style; dark theme has the LoomDraft background — panels use bg-card).
</decisions>
