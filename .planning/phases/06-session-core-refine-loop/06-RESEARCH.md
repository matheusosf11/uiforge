## Summary

The existing `GeneratorShell` derives "commit" from a `useEffect` watching `isLoading` flipping false plus several refs (`stoppedRef`, `failedRef`, `requestIdRef`). That design is race-prone and cannot express "keep the previous version while streaming". Phase 6 should replace it with a **pure reducer** (`src/lib/session.ts`) holding `versions[]`, `cursor`, `pending` (streaming text + request id + base id) and `error`, driven by a **small custom stream hook** instead of `useCompletion`. The commit decision is made in one place: when the awaited stream promise resolves `ok`, dispatch `COMMIT{requestId, raw}`; the reducer parses/validates and ignores any action whose `requestId` does not match `pending.requestId` (this is the stale-chunk guard).

`useCompletion` *can* technically be kept (per-call `body` is supported in the installed version) but it resets/shares global SWR state, swallows errors (resolves `undefined`), returns `null` on abort, keeps partial text in `completion` after errors, and does not abort an older in-flight request when a new `complete()` starts. A ~50-line `streamGenerate()` function (fetch + `ReadableStream` reader returning a discriminated result) removes all of that, is trivially unit-testable with an injected `fetch`, and fits the reducer flow. The server (Phase 5) is unchanged.

`/api/suggest` should use `generateText({ output: Output.object({ schema }) })` (v7 API; `generateObject` is `@deprecated`), a dedicated flash-lite-first model list, a **key-prefixed** call into the existing `checkRateLimit` (the limiter's `hits` Map is module-global, so "own bucket" = own key prefix + own config), an 8 s timeout, and an env-gated short-circuit mock. One real trap: `npx shadcn add alert-dialog` (v4.22) wants to install an npm package literally named `cn` and overwrite `button.tsx` - handle manually (see Standard Stack).

**Primary recommendation:** Reducer in `src/lib/session.ts` + `src/lib/stream-generate.ts` (custom fetch stream) + `use-generator-session.ts` hook + `use-suggestions.ts`; do NOT keep `useCompletion`; add `alert-dialog.tsx` by hand-fixing the shadcn output (import `cn` from `@/lib/utils`, keep existing `button.tsx`).

### Pattern 1: Session reducer (stale-chunk guard + commit/truncate/cap)
```ts
// src/lib/session.ts - sketch (names are discretionary)
export const MAX_VERSIONS = 20;
export type Version = { id: number; code: string; instruction: string; source: "ai" | "manual" /* Phase 8 */ };
export type SessionError =
  | { kind: "generate" | "refine" | "rate_limit" | "invalid"; instruction: string; baseId: number | null }
  | { kind: "too_large" };
export type Pending = { id: number; instruction: string; baseId: number | null; text: string };
export type SessionState = {
  versions: Version[]; cursor: number /* -1 = none */; pending: Pending | null;
  error: SessionError | null; nextVersionId: number; notice: "committed" | "undo" | "reset" | null;
};
export type Action =
  | { type: "START"; id: number; instruction: string }                // baseId := versions[cursor]?.id ?? null
  | { type: "CHUNK"; id: number; text: string }                        // full text so far (not delta)
  | { type: "COMMIT"; id: number; raw: string }
  | { type: "FAIL"; id: number; error: SessionError["kind"] }
  | { type: "ABORT"; id: number }
  | { type: "UNDO" } | { type: "RESET" };

// COMMIT: ignore if !pending || pending.id !== action.id.
// code = parseCode(raw); if (!code.trim() || !hasDefaultExport(code)) -> error {kind:"invalid"} (versions untouched)
// else: base = versions index of pending.baseId; kept = versions.slice(0, base + 1) (TRUNCATE, no redo);
//       next = [...kept, {id: nextVersionId, code, instruction, source:"ai"}]; if (next.length > MAX_VERSIONS) next.shift();
//       cursor = next.length - 1; pending = null; error = null.
// FAIL/ABORT: pending = null; versions/cursor untouched (ITER-07). ABORT sets error null.
// START while pending !== null: no-op (busy guard also in hook). START clears error.
// UNDO: only if pending === null && cursor > 0 -> cursor-1, error=null. Does NOT drop later versions (Phase 7 dims them; a later COMMIT truncates).
// RESET: initial state but keep nextVersionId monotonic (ids never reused -> suggestion cache keys stay unambiguous).
```
Display number is **index-based** (`cursor + 1` of `versions.length`), consistent with the 20-cap dropping the oldest (UI-SPEC: `v{cursor} de {total}`); the monotonic `id` is for cache keys/React keys only.

`baseId` captured at START (not recomputed at retry) is what makes "retry reuses the same base": the stored `error.baseId` + `error.instruction` are passed to `START` on retry; if undo/reset happened the error was already cleared. Edge: if the base was dropped by the 20-cap between failure and retry - impossible, cap only applies on commit.

### Pattern 2: Custom stream function (replaces `useCompletion`)
```ts
// src/lib/stream-generate.ts
export type StreamResult =
  | { ok: true; text: string }
  | { ok: false; reason: "aborted" }
  | { ok: false; reason: "http"; status: number; body: string }
  | { ok: false; reason: "stream"; error: unknown };   // network / mid-stream body error (Phase 5 errors the body)

export async function streamGenerate(
  body: { prompt: string; currentCode?: string },
  opts: { signal: AbortSignal; onText: (fullText: string) => void; fetchImpl?: typeof fetch },
): Promise<StreamResult> {
  const f = opts.fetchImpl ?? fetch;
  let res: Response;
  try {
    res = await f("/api/generate", { method: "POST", headers: { "content-type": "application/json" },
      body: JSON.stringify(body), signal: opts.signal });
  } catch (e) { return isAbort(e) ? { ok: false, reason: "aborted" } : { ok: false, reason: "stream", error: e }; }
  if (!res.ok) return { ok: false, reason: "http", status: res.status, body: await res.text().catch(() => "") };
  if (!res.body) return { ok: false, reason: "stream", error: new Error("empty_body") };
  const reader = res.body.pipeThrough(new TextDecoderStream()).getReader();
  let text = "";
  try {
    for (;;) { const { done, value } = await reader.read(); if (done) break; text += value; opts.onText(text); }
  } catch (e) { return isAbort(e) ? { ok: false, reason: "aborted" } : { ok: false, reason: "stream", error: e }; }
  return opts.signal.aborted ? { ok: false, reason: "aborted" } : { ok: true, text };
}
```
Error mapping: `http` 429 -> `friendlyGenerateError(new Error("rate_limited"))`; `http` 413 (or body `code_too_large`) -> `too_large`; other -> generic/refine message. A stream error after the first token (server `controller.error`) surfaces as a rejected `read()` -> `reason:"stream"` -> never promoted. A body that closes cleanly is by Phase 5 contract a `stop` finish [CITED: 05 route code: non-stop finish errors the body].

**Throttling:** dispatching `CHUNK` per network chunk re-renders `parseCode`+`CodeView` on each chunk (v1.0 did the same through SWR). Acceptable; optionally coalesce with `requestAnimationFrame`. Don't add a lib.

### Pattern 3: Hook orchestration
- `useReducer(sessionReducer, initial)` + `stateRef.current = state` each render (so `send` reads the latest `versions[cursor]` synchronously and so `send` is stable).
- Refs: `reqIdRef` (counter), `acRef` (current AbortController). `send(text)`: guard `pending` via `stateRef`; trim; client pre-check `base.code.length > MAX_CODE_LENGTH` -> dispatch START? No: dispatch `FAIL`-like `SET_ERROR {too_large}` without START (add action `REJECT{error}`) so no pending is created.
- `stop()`: `acRef.current?.abort(); dispatch({type:"ABORT", id: reqIdRef.current})` — ABORT clears pending immediately, so any chunk/commit arriving later carries a stale id and is ignored (PITFALLS #5).
- Return value of `send` (Promise<"committed"|"failed"|"aborted"|"ignored">) lets the shell clear the textarea **only on `committed`** (D-02) without an effect. Guard with the same id check so a stale resolution never clears text (use `reqIdRef.current === id` before returning `committed`; the reducer already ignored a stale COMMIT).
- `undo()`, `reset()` abort nothing (both disabled while busy; reset button disabled while busy per UI-SPEC). `useEffect` cleanup aborts on unmount.
- Unmount/StrictMode: AbortError path returns `aborted` and dispatches nothing.

### Pattern 5: Global Ctrl/⌘+Z
```ts
useEffect(() => {
  function onKeyDown(e: KeyboardEvent) {
    if (e.defaultPrevented || e.repeat || e.shiftKey || e.altKey) return;       // shift = redo, ignored
    if (!(e.ctrlKey || e.metaKey) || (e.key.toLowerCase() !== "z" && e.code !== "KeyZ")) return;
    const t = e.target as Element | null;
    if (t?.closest?.("input, textarea, select, [contenteditable]:not([contenteditable='false'])")) return;
    if (confirmOpen || document.querySelector('[role="alertdialog"]')) return;
    if (!canUndo) return;                                                        // !busy && cursor > 0
    e.preventDefault(); undo();
  }
  document.addEventListener("keydown", onKeyDown);
  return () => document.removeEventListener("keydown", onKeyDown);
}, [canUndo, confirmOpen, undo]);
```
Use `closest('[contenteditable]…')` rather than `isContentEditable`: jsdom's `isContentEditable` support is unreliable/absent [ASSUMED - not confirmed by the probe, which logged but output was suppressed], and `closest` covers nested nodes inside an editor (Phase 8's editor). The textarea is `disabled` while busy, so focus falls to `body` during streaming; the `canUndo` check (busy => false) is what blocks undo then. Test with `fireEvent.keyDown(document.body, {key:"z", ctrlKey:true})` and `userEvent` on the textarea (must NOT undo).

### Pattern 6: `/api/suggest`
```ts
// src/app/api/suggest/route.ts
import { generateText, Output } from "ai";
export const runtime = "nodejs"; export const maxDuration = 30;
const ModelOut = z.object({ suggestions: z.array(z.object({ label: z.string(), instruction: z.string() })).min(1).max(8) });

// 3. checkRateLimit(`suggest:${clientIp(req)}`, getSuggestRateLimitConfig())  -> 429 + Retry-After
// 4. isE2EMock(): return deterministic JSON (NO model call; code containing "__suggest_fail__" -> 502 for the fallback e2e)
// 5. no API key -> 500 (same message style)
// 6. for model of SUGGEST_MODEL_IDS (flash-lite first): try generateText({ model, system, prompt, output: Output.object({ schema: ModelOut }),
//      maxOutputTokens: 2048, timeout: 8000, abortSignal: req.signal, maxRetries: 0 }) ; on throw continue; none -> 502
// 7. sanitize: trim, drop empties/dupes, label.slice(0, 30) , instruction.slice(0, 300), take 4 ; 0 left -> 502
// 8. return Response.json({ suggestions })   // log only { evt:"suggest_usage", model, count } - never code
```
- `result.output` holds the parsed object [VERIFIED: `generate-text-result.ts:181 readonly output`]; on parse/schema failure the SDK throws `NoObjectGeneratedError` (caught -> next model / 502).
- Do not rely on the model honoring `.length(4)`/`max(30)`: Gemini's JSON-schema subset may ignore length keywords. Keep the model-facing schema lenient and **clamp server-side** (step 7). If fewer than 4 come back, client fills remaining slots from `FALLBACK_SUGGESTIONS` (dedupe by label) so the UI always shows 4.
- **Model list:** add `export const SUGGEST_MODEL_IDS = ["gemini-3.5-flash-lite", "gemini-3.6-flash"] as const` to `src/lib/ai/model.ts` (both ids exist in the installed provider's id union [VERIFIED]); the last entry of the generate chain is already `gemini-3.5-flash-lite`. Thinking tokens count against `maxOutputTokens` (Phase 5 finding), so use 2048 not 256.
- **Rate limit (own bucket):** `checkRateLimit`'s `hits` Map is module-global and keyed only by the string -> pass key `suggest:${ip}` and its own config (`SUGGEST_RATE_LIMIT_MAX` default 10 / `SUGGEST_RATE_LIMIT_WINDOW_MS` default 60000; add `getSuggestRateLimitConfig()` in `rate-limit.ts`). Shared `MAX_KEYS` cap is fine. Playwright webServer env must add `SUGGEST_RATE_LIMIT_MAX: "1000"` (all e2e traffic shares IP `"unknown"`); document in `.env.example` (file currently has uncommitted edits - planner must not clobber them).
- **Client** `useSuggestions(current: {id, code} | null)`: `cache: Record<number, Suggestion[]>` (ref+state), `loadingId`. Effect on `current?.id`: no current -> nothing; cached -> nothing; else `AbortController` + `AbortSignal.timeout(10_000)`; on resolve `setCache(id -> list)` **keyed by the id that was requested** (that IS the stale guard: the chip row always reads `cache[current.id]`, so a late response for v2 can only fill v2's slot); on any failure `cache[id] = FALLBACK` silently; cleanup aborts the in-flight request when `id` changes or on unmount; `reset` clears the cache. While `pending` (refine streaming) the effect does not fire (id unchanged) and the previous chips render disabled; after COMMIT a new id triggers a fetch (skeleton until it lands). No `useSWR` needed.
- Skeleton shows when `current && cache[current.id] === undefined`.

### Anti-Patterns to Avoid
- **Deriving commit from `isLoading` effects/refs** (today's shell): move to promise-result + reducer.
- **Truncating at START**: truncate at COMMIT only, else a failed refine from an old version would destroy history (PITFALLS #9/#5).
- **Unmounting the iframe while streaming** (flash): keep SandboxPreview mounted.
- **Clearing the prompt in an effect on `versions.length`**: use the `send()` result.
- **Using `useSWR`/`useCompletion` global keys** for new state.
- **Sharing the rate-limit key with generate**.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Structured model output | manual JSON-from-text parsing / regex | `generateText` + `Output.object({schema})` | SDK sets provider `responseFormat`, parses and validates |
| Modal focus trap / Esc / aria | custom overlay | Base UI `AlertDialog` (via shadcn wrapper) | focus trap, inert, scroll lock, `role=alertdialog` verified in jsdom |
| Text-stream decoding | manual `TextDecoder` chunk stitching | `res.body.pipeThrough(new TextDecoderStream())` | handles multi-byte split across chunks (same as SDK's `processTextStream`) |
| Code fence/export validation | new regex | `parseCode`, `hasDefaultExport` | already tested |
| Rate limiting | new limiter | `checkRateLimit` with a prefixed key | exists; D-09 trade-offs documented |
| Friendly errors | new strings | `friendlyGenerateError`, constants | fixed pt-BR copy locked |

**Key insight:** the complexity is in *state transitions* (commit/abort/stale), not in libraries - isolate it in one pure, exhaustively unit-tested reducer.

## Common Pitfalls

### Pitfall 1: `useCompletion` quirks (if someone keeps it)
**What goes wrong:** `complete()` resolves `undefined` on error (and `onError` fires), `null` on abort; `completion` is reset to `''` at the start of every call and keeps partial text after errors/abort; a second `complete()` does not abort the first fetch (only ignores its chunks via `isCurrentRequest`). `onFinish(prompt, result)` fires only on clean completion and does give the full text. `stop()` aborts, `complete()` resolves `null` (does not reject). [VERIFIED: `node_modules/ai/src/ui/call-completion-api.ts`, `@ai-sdk/react/src/use-completion.ts`]
**How to avoid:** use `streamGenerate` (above). The v1.0 shell compensated with `failedRef`/`stoppedRef` - exactly the fragility to remove.

### Pitfall 2: shadcn `add alert-dialog` side effects
Installs npm `cn` and overwrites `button.tsx` (see Standard Stack). Verify `git diff --stat` after running.

### Pitfall 3: Server 200-then-error
Status is already 200 when the body errors; `res.ok` is true. Only a rejected `reader.read()` signals failure. `streamGenerate` must treat a thrown read as failure and **never** commit `text` in that case (ITER-05). Also empty/whitespace body -> `COMMIT` rejects as `invalid`.

### Pitfall 4: Stale async continuation
After Parar + fast resend, the old `streamGenerate` may still resolve. Every dispatch carries `id`; reducer ignores mismatches; `send()` returns `"aborted"`/`"ignored"` so the shell doesn't clear the prompt.

### Pitfall 5: Undo with `future` versions then refine
UNDO keeps later versions; COMMIT truncates after the base. Phase 7 will render the kept ones - do not delete them in UNDO. Test: v1,v2,v3 -> undo -> undo -> refine => [v1, v4'] (cursor 1).

### Pitfall 6: Error banner duplicates
When a refined version has a preview runtime error, SandboxPreview's own alert shows a button "Tentar de novo" while the shell banner may too -> Playwright `getByRole('button',{name:'Tentar de novo'})` strict-mode violation. Banner and preview alert are mutually exclusive in practice (banner = request failure, preview alert = post-commit runtime failure) but guard with tests.

### Pitfall 7: e2e substring matching
Playwright `getByRole("button",{name:"Gerar"})` is substring/case-insensitive: it also matches "Gerar de novo". Existing specs only click it before any preview exists, so OK. After first commit the primary button is "Refinar".

### Pitfall 8: `Pronto` status
Existing e2e use `page.getByText("Pronto")` -> "Pronto — v1" still matches (substring). Keep exactly one element containing "Pronto" (do not duplicate in a toast/aria-live twin) or strict mode fails.

### Pitfall 9: Rate-limit key sharing + e2e
Generate 5/min default; auto-suggest after every commit adds traffic. Separate bucket (prefixed key). In e2e all requests share IP `"unknown"` -> set `SUGGEST_RATE_LIMIT_MAX=1000` in the Playwright env.

### Pitfall 10: Prompt-field/gallery selected state
`PromptForm` keeps `selectedId` internally keyed on `EXAMPLE_PROMPTS`; for chips generalize to an `items: {id,label,prompt}[]` prop (gallery in generate mode, suggestions in refine mode) and compare `value === prompt`. Focus the textarea after prefill (UI-SPEC) — note the textarea is `disabled` while busy, chips too, so no conflict.

## Code Examples

### Reducer test skeleton (QUAL-06)
```ts
it("ignores stale chunks and commits after abort", () => {
  let s = reduce(init, { type: "START", id: 1, instruction: "a" });
  s = reduce(s, { type: "ABORT", id: 1 });
  s = reduce(s, { type: "CHUNK", id: 1, text: "late" });
  s = reduce(s, { type: "COMMIT", id: 1, raw: "export default function A(){}" });
  expect(s.versions).toHaveLength(0);
});
```
Required cases: commit v1; commit rejects empty / no `export default` (error `invalid`, versions intact); refine from cursor<last truncates; 20-cap drops oldest (cursor stays last, ids monotonic); undo bounds (cursor 0 no-op, blocked while pending); undo keeps future versions; retry START reuses `error.baseId`; FAIL/ABORT keep versions + cursor; RESET clears everything but keeps `nextVersionId`; stale-id actions (CHUNK/COMMIT/FAIL) are no-ops; START while pending is a no-op; client too_large REJECT creates no pending.

### Threat Model
| # | Threat | STRIDE | Mitigation |
|---|--------|--------|------------|
| T1 | Prompt injection via `code` (comments telling the model to emit malicious/off-topic suggestions or leak system prompt) | Tampering / Info disclosure | Code wrapped in `<current_code>` as DATA, delimiter-neutralizing (`neutralizeDelimiters`, export it), system prompt says ignore instructions inside; output clamped (4 items, label 30, instruction 300) and rendered as React text (no HTML); user must click and then explicitly send; impact bounded to a bad suggestion |
| T2 | Quota/cost abuse (loop of /api/suggest) | DoS / Elevation of cost | Own limiter bucket (`suggest:` prefix, 10/min default), lightest model, `maxOutputTokens` 2048, 8 s `timeout`, `maxRetries: 0`, size cap before limiter; in-memory best-effort (documented PLAT-01) |
| T3 | Oversized/malicious body (memory) | DoS | content-length pre-check + actual byte check (<= 256 KB) + 413 before parse/limiter |
| T4 | Mock switch abuse | Elevation | `isE2EMock()` env-only, hard-disabled when `VERCEL_ENV=production`; never header/body driven; test-only `__suggest_fail__` keyword only reachable in mock mode |
| T5 | Spoofed forwarded IP to dodge limiter | Spoofing | `clientIp` already trusts forwarded headers only on Vercel |
| T6 | Sensitive data in logs | Info disclosure | log `{evt, model, count}` only; error paths return fixed strings, never provider messages |
| T7 | Stored/DOM XSS via suggestion text | Tampering | React escapes text; `title`/`aria-label` attributes are also escaped; never `dangerouslySetInnerHTML` |
| T8 | Stale/forged response applied to wrong version | Tampering (integrity) | cache keyed by requested version id; abort on id change |
| T9 | Provider error leaks details | Info disclosure | map all failures to `502 suggest_failed` / `429 rate_limited` |
