# Phase 7 — UI Design Contract

> Visual and interaction contract for Turn List & Version Navigation. Generated by gsd-ui-researcher, verified by gsd-ui-checker. Decisions D-01..D-20 from 07-CONTEXT.md are locked and reflected here. Everything else is a Claude's-discretion choice, marked "(default)". Tokens, type scale, colors and copy conventions are inherited from the approved `06-UI-SPEC.md`.

> **Focal point:** the preview stays the primary visual anchor and the textarea stays the primary action area. The turn list is a compact, secondary navigation surface. It must never push the textarea or chips out of view on desktop (D-01).

## Spacing Scale

Declared values (multiples of 4). The Tailwind unit is 4px.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Gap between list items (`gap-1`), list inner padding (`p-1`), badge horizontal padding (`px-1`) |
| sm | 8px | Item horizontal padding (`px-2`), gap between label, text and icon in an item (`gap-2`), item row height is fixed by `h-8` (32px; no vertical padding), bottom margin of the base notice (`mb-2`) |
| md | 16px | Panel padding (inherited `p-4`) |
| lg | 24px | Not used newly |
| xl | 32px | Item row height on desktop (`h-8`) |
| 2xl | 48px | Not used newly |
| 3xl | 64px | Not used newly |

The list block sits directly under the session bar. It has `mb-4` (16px) before the panel title.

Exceptions:
- The current item's left border is `border-l-2` (2px). Every item carries `border-l-2 border-transparent` so text never shifts when the current item changes.
- The "atual" badge is `h-4` (16px) with no vertical padding.
- List max height: `max-h-44` (176px = 5 rows × 32px + 4 gaps × 4px) on desktop. On mobile it is `max-md:max-h-60` (240px, about 5 rows of 44px). Intentional: container padding/border (and the cap line when shown) leave about 4.6 visible rows, so a partially cut row signals that the list scrolls (D-01 "about 5").
- Mobile touch targets: every item button and the disclosure button get `max-md:min-h-11` (44px), as inherited.

Declared set: sizes 12 / 14 / 16 (16 only in the existing AlertDialog title); weights 400 and 500. The "vN" label, the badge and the session counter use `tabular-nums`. The instruction text is on 1 line with `truncate` (D-05).

## Color

Existing oklch tokens only. Dark theme values are shown; a light analog exists.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` oklch(0.145 0 0) + LoomDraft canvas | Page background; also the "atual" badge fill (`bg-background`) inside the muted current row |
| Secondary (30%) | `--card` oklch(0.205 0 0), `--muted` oklch(0.269 0 0), `--border` | Prompt panel (card); current item background (`bg-muted`, D-07); item hover (`hover:bg-muted/60`); list frame (`border border-border rounded-lg`) |
| Accent (10%) | `--primary` oklch(0.922 0 0) | See reserved list |
| Destructive | `--destructive` oklch(0.704 0.191 22.216) | `AlertTriangle` icon of the transient error item (`text-destructive`, D-06), the existing error banner and the existing AlertDialog confirm |

Accent reserved for:
1. The primary submit button "Gerar"/"Refinar" (inherited).
2. The selected suggestion or example chip (inherited).
3. The 2px left border of the current turn item (`border-primary`, D-07).

Nothing else in the list uses primary: `Check` is `text-muted-foreground`, `Loader2` is `text-muted-foreground`, and the badge is neutral.

The current state never relies on color alone (D-07). It combines three cues: background, left border and the visible "atual" badge, plus `aria-current="true"`.

Later versions (after a restore) are dimmed with `opacity-50` applied to the instruction text and the status icon only; the `vN` label stays `text-foreground` at full opacity so the clickable item keeps a readable, contrast-compliant anchor (D-08; verify contrast in both themes). There is no strikethrough and no hue change. On hover and on focus-visible they go back to `opacity-100` so the text stays readable while being targeted (default).

## Component Contracts

### 1. Placement in the prompt panel (D-01, D-02, D-04)

The order inside `PromptForm`'s `<section>`, top to bottom:

1. `SessionBar` (existing, adapted, see §6)
2. **Turn list block** (new; passed in as a slot next to `sessionBar`, e.g. `turnList?: ReactNode`)
3. `h2` "Refinar componente" (unchanged)
4. **Base notice** line (new, only when needed, see §5)
5. Textarea, char counter, chips, buttons (unchanged)

The block renders only when `versions.length >= 1`, the same condition as the session bar (D-04). During the first generation and after a failed first generation there is no list; the banner alone covers it.

### 2. Turn list block (`turn-list.tsx`)

Structure (default):

```
<div class="mb-4">
  [mobile only] disclosure button
  <div id="turn-list-region" class="max-h-44 max-md:max-h-60 overflow-y-auto overscroll-contain rounded-lg border border-border p-1 [collapsed: max-md:hidden]">
    [cap line, only when droppedCount > 0]
    <ol aria-label="Histórico de versões" class="flex flex-col gap-1">
      <li> TurnItem (one per kept version, oldest first) </li>
      <li> transient item (gerando or erro), at most one, always last </li>
    </ol>
  </div>
</div>
```

- Order: oldest at the top, newest at the bottom, next to the field (D-03).
- Own scroll; the page does not grow beyond about 5 rows (D-01).
- **Auto-scroll (D-03):** after each commit, undo, restore and when a transient item appears, scroll the list region so the current item (or the transient item, if any) is visible. Scroll **only the list container**, by adjusting `scrollTop` so the item is fully inside it (an equivalent of `block: "nearest"`). Do not call a bare `element.scrollIntoView()`, because that also scrolls the page and would jump the mobile viewport. No smooth scrolling; the jump is instant, so no reduced-motion variant is needed.
- **Cap line (D-17):** a `<p class="px-2 py-1 text-xs text-muted-foreground">Versões mais antigas descartadas (limite de 20)</p>`, rendered inside the scroll region above the `<ol>`. It is not a list item, so it does not count as a turn. It is shown when `droppedCount > 0` (the cap has evicted at least one version). Do not test version ids: they are internal and keep counting across resets and regenerations.

### 3. Mobile disclosure (D-02)

- One DOM list for both breakpoints. There are no duplicated ids or items.
- Disclosure trigger, mobile only (`md:hidden`): `Button variant="ghost" size="sm"` with classes `w-full justify-between max-md:min-h-11`, label `Histórico ({N})`, where N is `versions.length` (kept versions only; the transient item is not counted). It has `aria-expanded={open}` and `aria-controls="turn-list-region"`.
- A trailing `ChevronDown` icon (`aria-hidden`) gets `rotate-180` when open, with `transition-transform motion-reduce:transition-none`.
- Collapsed: the region has `max-md:hidden`. On `md+` the region is always visible and the trigger is hidden.
- Collapsed by default. The open state lives in shell memory (`useState`) for the session, with no storage. "Novo componente" (reset) sets it back to collapsed. Commit, undo and restore do not change it.
- When open, a mobile margin `mt-1` (4px) separates the trigger from the region (default).

### 4. Turn item (`turn-item.tsx`) (D-05..D-10)

Shared row layout: `flex w-full min-w-0 items-center gap-2 rounded-md border-l-2 border-transparent px-2 h-8 max-md:min-h-11 text-left text-xs`.

| Slot | Content | Classes |
|------|---------|---------|
| Label | `v{n}` (stable display number = droppedCount + index + 1, D-17) | `min-w-7 shrink-0 font-medium tabular-nums text-foreground` |
| Text | instruction (v1 = original prompt). For `source: "manual"`, show `Edição manual` (D-05; Phase 8 creates these) | `min-w-0 flex-1 truncate text-muted-foreground` (current item: `text-foreground`) |
| Badge (current only) | `atual` | `inline-flex h-4 shrink-0 items-center rounded-sm bg-background px-1 text-xs leading-4 font-medium text-foreground` |
| Status icon | see the state table | `size-4 shrink-0` (16px), `aria-hidden="true"` |

The `title` attribute always holds the full instruction text, or `Edição manual`.

**States:**

| State | Element | Visual | Accessible name / text | Interaction |
|-------|---------|--------|------------------------|-------------|
| Version, not current, before the cursor | `<button type="button">` | default row, hover `hover:bg-muted/60`, `Check` in `text-muted-foreground` | `aria-label="Restaurar v{N}: {texto}. Concluída."` | click, Enter or Space restores (D-12) |
| Version, current | `<button type="button" aria-current="true">` | `bg-muted border-primary`, text `text-foreground`, badge `atual`, `Check` | `aria-label="v{N}, versão atual: {texto}. Concluída."` | click is a no-op (no reducer action, no announcement) |
| Version after the cursor (dimmed) | `<button type="button">` | instruction text + icon `opacity-50` (vN label full opacity), back to `opacity-100` on hover/focus-visible, `Check` | `aria-label="Restaurar v{N}: {texto}. Concluída. Será descartada ao refinar."` | restores normally; works as implicit redo (D-13) |
| Transient: gerando (D-09) | non-interactive `<div>` inside the `<li>` (no button) | empty label slot (`min-w-7`), instruction, then a visible `gerando…` (`text-xs text-muted-foreground`) and `Loader2` with `animate-spin motion-reduce:animate-none text-muted-foreground` | content read as `Gerando: {texto}` (an `sr-only` prefix `Gerando: ` before the text; the visible word `gerando…` is `aria-hidden`) | none |
| Transient: erro (D-10) | non-interactive `<div>` | empty label slot, instruction, then a visible `erro` (`text-xs text-destructive`) and `AlertTriangle` in `text-destructive` | `sr-only` prefix `Erro: ` before the text; the visible word is `aria-hidden` | none; "Tentar de novo" stays only in the banner (single retry button, Phase 6 WR-01) |

Rules:
- **While streaming** (`busy`), every version button is `disabled` (D-09). There is no extra opacity change for disabled; the gerando item signals the busy state, which avoids flicker on every refine. Use `disabled:pointer-events-none disabled:cursor-default`. Dimmed items keep their dimmed instruction/icon.
- The gerando item turns into the new `v{N}` item with `Check` on commit. The new item becomes current and the list scrolls to it.
- **Parar** (stop) removes the gerando item with no trace (D-11).
- The **erro** item is removed on a successful retry (replaced first by gerando), a new send, undo, restore or reset (D-10).
- Repeated instructions are separate items (D-05). There are no timestamps.
- No list enter or exit animations (deferred).

### 5. Base notice (D-15)

- Shown only when the current version is not the last kept one (`cursor < versions.length - 1`). It is placed between the `h2` and the textarea: `<p id="refine-base-notice" class="mb-2 text-xs text-muted-foreground">`.
- It stays visible while a refinement from that base is streaming, because the truncation only happens at commit. It disappears after the commit.
- The textarea gets `aria-describedby="refine-base-notice prompt-char-count"` while the notice is shown, and only `prompt-char-count` otherwise. The notice is **not** a live region; the status line announces navigation.
- The button label stays `Refinar`. There is no confirmation dialog: the notice is the warning for this implicitly destructive action (D-12, D-15).

| Later versions | Copy |
|----------------|------|
| 2 or more (vX..vY) | `Refinar a partir da v{N} — v{X} a v{Y} serão descartadas` |
| exactly 1 (vX) | `Refinar a partir da v{N} — v{X} será descartada` |

N, X and Y are stable display numbers (D-17).

### 6. Session bar adaptation (D-17)

- Counter changes from `v{N} de {M}` to `v{N} · {M} versões`, where N is the stable display number of the current version and M is `versions.length`. Singular: `v{N} · 1 versão`. Classes unchanged (`text-xs text-muted-foreground tabular-nums`).
- `Desfazer` and `Novo componente` are unchanged. Undo is cursor − 1 from whatever is current (D-14).

### 7. Restore behavior (D-12, D-13, D-16, D-19)

On clicking a non-current version:
1. The cursor moves to it instantly, with no confirmation.
2. The code panel shows its code and **scrolls to the top**.
3. The preview swaps directly. There is no "Atualizando…" badge (that badge is only for streaming) and no placeholder.
4. Any session error banner and transient erro item are cleared.
5. Suggestion chips switch to that version's chips: from the cache if present, otherwise the skeleton then the fetch. Never show another version's chips (D-16).
6. The status line announces (§8).
7. **Focus stays on the clicked item** (D-19). Re-render must keep the same element: key items by version id.
8. Mobile: the active Preview/Código tab is unchanged, and the disclosure stays open.

After reset ("Novo componente"): the list unmounts, the disclosure goes back to collapsed, and focus goes to the textarea (existing Phase 6 WR-03 behavior).

### 8. Status line (D-20, D-17)

Same single `aria-live="polite"` region. All numbers are stable display numbers (droppedCount + index + 1), never raw version ids.

| Situation | Text |
|-----------|------|
| Commit | `Pronto — v{n}` (e2e string kept) |
| Undo or restore to an earlier version | `Voltou para v{n}` (e2e string kept) |
| Restore to a later, dimmed version | `Foi para v{n}` |
| Click on the current item | no change |
| Refining / first generation / reset / stop / error | unchanged from Phase 6 (`Refinando…`, `Gerando…`, `Novo componente iniciado`, empty, empty) |

The list itself has no live regions. The session counter is not live.

### 9. Keyboard and focus (D-18, D-19)

| Input | Behavior |
|-------|----------|
| Tab / Shift+Tab | Order: session bar (Desfazer, Novo componente), [mobile] disclosure button, each version item from oldest to newest, then textarea, chips, Refinar, Parar. Transient items are not focusable. No roving tabindex. |
| Enter / Space on an item | Restores it (native button) |
| Enter / Space on the disclosure | Toggles open/closed |
| Ctrl/⌘+Z with focus on an item | Undo works, because the target is a button and not a text field (inherited rule). Focus stays on that button. |

The focus ring on items is `focus-visible:ring-3 focus-visible:ring-ring/50 outline-none`. The ring must not be clipped by the scroll container: the container has `p-1`, which leaves room for the ring.

### 10. Motion

The only new motion is the `Loader2` spin on the gerando item (`motion-reduce:animate-none`, so it is static under reduced motion, D-06) and the chevron rotation (`motion-reduce:transition-none`). There are no list animations, no smooth scroll and no fade on restore.
